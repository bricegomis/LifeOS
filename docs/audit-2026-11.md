## A. Bugs probables

- [ ] **A1 — Routes d'ingrédients en double.**
  `CatalogManagementEndpoints.cs` et `RecipesEndpoints.cs` déclarent tous deux
  PUT/DELETE `/api/recipes/{id}/ingredients/{ingredientId}`. La version
  CatalogManagement (contrainte `:guid`) gagne toujours ; celle de Recipes n'est
  jamais atteinte et ne répond pas pareil (`204` vide contre la recette complète).
  → Garder une seule version dans Recipes, supprimer CatalogManagement.
- [x] ~~**A2 — Création de semaine bloquée par une semaine invisible.**~~ Sans objet : semainier retiré (ADR 0008).
  `ManualPlannerEndpoints.CreateWeekAsync` refuse la date si n'importe quelle
  semaine existe, alors que la liste et la duplication filtrent sur `IsManual`.
  D'anciennes semaines générées peuvent donc bloquer la création sans être visibles.
  → Aligner le contrôle, vérifier ce qu'il y a en prod, puis retirer `IsManual` à terme.
  Ajouter un test de non-régression.
- [x] ~~**A3 — `ActivitySession` sans `household_id`.**~~ Sans objet : semainier retiré (ADR 0008).
  Le filtrage passe par jour → semaine. C'est correct, mais ça contredit la règle
  « chaque ligne métier porte son `household_id` ».
  → Migration additive + clé étrangère composite + test d'isolation.
- [ ] **A4 — Message 409 générique.**
  `ApiExceptionHandler` renvoie « Ce raccord ou cette semaine existe déjà » pour
  toute violation d'unicité (23505).
  → Choisir le message d'après `PostgresException.ConstraintName`.
