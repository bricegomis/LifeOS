# Audit du code — novembre 2026

Revue du dépôt faite le 2026-11-08 (lecture du code, sans exécution des tests).
Ne restent ici que les points ouverts ; les points livrés ou devenus sans objet
avec le retrait du semainier ont été retirés (voir l'historique git).
Chaque point garde son identifiant. Ils sont à traiter ou à fermer pendant
l'étape 1 de la [roadmap](01-roadmap.md).

## A. Bugs probables

- [ ] **A4 — Message 409 générique.**
  `ApiExceptionHandler` renvoie « Ce raccord ou cette semaine existe déjà » pour
  toute violation d'unicité (23505).
  → Choisir le message d'après `PostgresException.ConstraintName`.

## C. Performance (requêtes en cascade)

- [ ] **C3 — Page Aliments.** Une requête `/reviews/foods/{id}` par aliment
  (`food-items-page.component.ts`). → Renvoyer le résumé des avis (moyenne,
  nombre) dans `GET /api/foods`.
- [ ] **C4 — Images d'aliments.** Un blob par image, sans cache. → Ajouter `ETag`
  ou `Cache-Control: private`.

## D. Structure du backend

- [ ] **D1** — Résolution utilisateur → foyer répétée dans environ 80 handlers.
  → Filtre de groupe ou paramètre lié `HouseholdContext`.
- [ ] **D2** — Supprimer les `try/catch (ArgumentException)` redondants : le
  gestionnaire global renvoie déjà un 400.
- [ ] **D3** — Couches : seules les recettes passent par un repository, le reste
  utilise directement le `DbContext` depuis l'API.
  → ADR 0009 : accès direct permis pour la gestion simple, cas d'usage pour les
  actions à règles ; un seul style par cas, et suppression de `IRecipeRepository`
  si les recettes relèvent de la gestion simple.
- [ ] **D4** — Déplacer `FoodImageStorage` et `ReceiptPhotoStorage` (API) vers Infrastructure.

## E. Frontend

- [ ] **E1** — Passer en mode zoneless : `provideZonelessChangeDetection()`, retirer
  `zone.js` des polyfills, vérifier les pages qui utilisent `ngModel`.
- [ ] **E2** — Découper les gros composants (foods, tickets, recipes :
  400 à 470 lignes avec template inline) : templates en `.html`, logique dans des
  modules `.ts` testables.
- [ ] **E3** — Découper `src/styles.css` (2 100 lignes) par fonctionnalité.
- [ ] **E4** — Renommer `VITE_LIFEOS_API_URL` (reste de Vue) en `LIFEOS_API_URL`,
  avec une période de transition.
- [ ] **E5** — Déplacer `@capacitor/cli` dans `devDependencies`.
- [ ] **E6** — Fusionner `getBlob` avec `request` dans `lifeos-api.service.ts`.
